# 运维手册 · 企业身份集成（LDAP/AD 透传认证）

> 适用版本：T3 企业身份集成（`auth_source` / `external_dn`，迁移 `0007`）及之后。
> 读者：负责部署与值守 IPIP 的运维工程师。
> 目标：按本手册可**独立完成**接入、排错与回滚，无需读源码。

---

## 0. 一句话原理

登录时把**用户当次输入的密码**原样送到域控做一次 Bind 校验：

```
浏览器 --密码--> IPIP --原样透传--> AD/LDAP
                    <-- 通过/拒绝 ---
```

- IPIP **不保存、不缓存、不落库**任何 LDAP 密码，也不做密码同步。
- 域控说通过 → IPIP 按本地账号签发自己的 JWT 会话（`auth_type=ldap`）。
- 域控说拒绝 / 不可达 → **直接失败**，不会退回本地密码校验（见 §5 与 §9）。

---

## 1. 边界与铁律

| 铁律 | 说明 | 为什么 |
|---|---|---|
| 只读透传 Bind | 只做校验，不写域控 | 避免密码同步带来的凭据扩散 |
| 不可降级 | 域控不可达时明确报错，**绝不回落本地密码** | 否则"能访问域控的人"可以关掉域控来绕过 |
| 失败原因只进日志 | 终端用户始终看到「用户名或密码错误」 | 防止用不同提示做账号枚举 |
| 角色来源单一 | 映射表为空 = 角色由本地管理员维护 | 避免"开了 LDAP 就把存量角色洗成空" |
| 开关默认关闭 | `LDAP_ENABLED` 默认 `false` | 存量部署升级后行为与性能完全不变 |

## 2. 配置项清单

配置写在 `/etc/ipip/ipip.env`（由 systemd `EnvironmentFile` 注入，勿写入仓库）。

| 变量 | 默认 | 必填 | 说明 |
|---|---|---|---|
| `LDAP_ENABLED` | `false` | — | 总开关。`false` 时以下各项全部无效 |
| `LDAP_SERVER` | 空 | ✅ | `ldaps://dc.corp.local:636`（推荐）或 `ldap://dc:389` |
| `LDAP_BASE_DN` | 空 | ✅ | 检索起点，如 `DC=corp,DC=local` |
| `LDAP_BIND_DN` | 空 | — | 检索用服务账号；留空 = 匿名绑定（多数 AD 不允许） |
| `LDAP_BIND_PASSWORD` | 空 | — | 服务账号口令 |
| `LDAP_USER_FILTER` | `(sAMAccountName={username})` | — | AD 用 `sAMAccountName`，OpenLDAP 常用 `uid`；`{username}` 会被 RFC 4515 转义 |
| `LDAP_TIMEOUT` | `5` | — | 连接/检索/Bind 超时（秒） |
| `LDAP_GROUP_ROLE_MAP` | 空 | — | 组→角色映射，见 §4；**留空 = 角色不由目录托管** |
| `LDAP_DEFAULT_ROLE` | 空 | — | 没有任何组命中时的兜底角色；留空 = 判为未授权并**拒绝登录** |
| `LDAP_AUTO_PROVISION` | `false` | — | 首次登录自动建号（会写库），见 §5 |
| `LDAP_SYNC_ROLES_ON_LOGIN` | `true` | — | 每次登录按组重算角色（仅映射表非空时生效） |
| `LDAP_BYPASS_USERS` | 空 | — | 应急本地通道白名单，见 §6 |

### 启动期自检（fail-fast）

服务启动即报错，不会等到"第一个用户登不上"才暴露：

1. `LDAP_ENABLED=true` 但 `LDAP_SERVER` 或 `LDAP_BASE_DN` 为空 → `RuntimeError`；
2. `LDAP_ENABLED=true` 且 `LDAP_GROUP_ROLE_MAP` 写法非法 → `RuntimeError`。

`LDAP_ENABLED=false`（默认）时**不做任何校验**，即使误留一份写错的映射表也不影响启动。

## 3. 部署与升级步骤

```bash
# 1) 停服前备份（备份手册见《运维手册-备份与恢复》）
python3 scripts/backup_system.py

# 2) 升级代码 + 安装依赖（ldap3 为纯 Python 包，无需系统 libldap）
pip install -r requirements.txt

# 3) 执行表结构迁移（新增 users.auth_source / users.external_dn + 索引）
cd /opt/ipip && MONITOR_ENABLED=false flask db-upgrade
flask db-status          # 期望：链头已到 0007

# 4) 写入 LDAP 配置（见 §2），先保持 LDAP_ENABLED=false 启动一次
systemctl restart ipip.target
systemctl is-active ipip-web ipip-monitor   # 确认基础服务正常

# 5) 配置自检：必填项、映射语法、以及映射表/默认角色指向的每个角色
#    都必须已存在且启用（**不需要连域控**，失败以退出码 1 报警）
flask ldap-check

# 6) 打开开关并重启（此时才开始走企业认证）
#    LDAP_ENABLED=true
systemctl restart ipip.target
```

> ⚠️ **安装脚本陷阱**：`install.sh` 只把 schema 覆盖到 baseline 声明范围，**不会**执行
> `flask db-upgrade`。全新安装后必须手工执行第 3 步，否则 `auth_source` 列不存在，
> 登录会直接报错。

> ⚠️ **上线前先做 §10 的联调验收**，不要在没验证过的域控上直接放开。

## 4. 组→角色映射

### 4.1 写法（三种，任选）

```bash
# ① 规范分隔串（推荐手写）：条目间用 ; 或 | 或换行，组与角色间用 =>
LDAP_GROUP_ROLE_MAP=IPIP-Ops=>operator;IPIP-Viewers=>viewer
LDAP_GROUP_ROLE_MAP=cn=admins,ou=groups,dc=ipip,dc=local:admin|cn=engineers,ou=groups,dc=ipip,dc=local:engineer

# ② JSON（推荐脚本生成）
LDAP_GROUP_ROLE_MAP={"IPIP-Ops": "operator", "CN=IPIP-Admins,OU=Groups,DC=corp,DC=local": "admin"}
```

分隔符规则（**DN 里全是 `=`，所以这里必须守规矩**）：

| 位置 | 可用 | 约束 |
|---|---|---|
| 条目之间 | `;`、`|`、换行 | 任选，可混用 |
| 组与角色之间 | `=>`（推荐） | 无约束，DN 里不可能出现 `=>` |
| 组与角色之间 | `:` 或 `=` | **该条目里只能出现一次**，否则启动期报错 |

> ⚠️ 最常见的写错方式：多条映射用**逗号或空格**并列。这类串会被当成**一条**映射
> 切开，键值全是垃圾，垃圾键永远匹配不上任何组 —— 症状是「所有人都被降级到
> `LDAP_DEFAULT_ROLE`」，不报错、日志干净、配置看着还挺对。现在这种写法会在
> **启动期直接报错**（`LDAP_GROUP_ROLE_MAP 无法解析`），不会再静默降级。

角色名必须是 IPIP 里**已存在且启用**的角色（`roles` 表；内置：`admin` / `operator` / `viewer` / `user`）。
角色名不得包含空白、逗号、分号、等号、竖线、冒号。

### 4.2 键怎么匹配（AD / OpenLDAP 差异）

`memberOf` 返回的是完整 DN，例如 `CN=IPIP-Ops,OU=Groups,DC=corp,DC=local`。
匹配时该 DN 会展开成这些**精确键**：

| 可用的键 | 是否可匹配 |
|---|---|
| `CN=IPIP-Ops,OU=Groups,DC=corp,DC=local`（完整 DN） | ✅ |
| `IPIP-Ops`（CN 值） | ✅ |
| `Groups`（OU 值） | ✅ |
| `corp` / `local`（DC 值） | ❌ **刻意不支持** |

- 只做**精确匹配**，不做子串：写 `Ops` **不会**命中 `IPIP-Ops`（防误授权）。
- 大小写不敏感。
- 刻意不收 `dc=` 值：否则配一个 `corp` 就等于把整棵树都授权了。

### 4.3 角色语义

| 场景 | 行为 |
|---|---|
| 映射表**为空** | 角色由本地管理员维护；登录**不改动**任何既有角色（推荐起步形态） |
| 映射表非空，命中 | 每次登录按命中结果重算角色（组变更下次登录即生效） |
| 映射表非空，未命中任何组 | 用 `LDAP_DEFAULT_ROLE`；若也没配 → **拒绝登录**（不留无角色会话） |
| 目录映射结果为空集 | 角色同步**拒绝清空**既有角色（防一次目录异常把人清零） |
| 映射到不存在/已停用的角色 | 该角色告警跳过；若最终一个都不剩 → 按"未授权"处理 |

## 5. 首次登录自动建号

`LDAP_AUTO_PROVISION=false`（默认）：目录通过但本地无账号 → **拒绝登录**，日志出现
`LDAP 认证通过但本地无对应账号，自动建号未启用`。

`LDAP_AUTO_PROVISION=true`：

- 自动创建本地账号：`auth_source=ldap`、`external_dn=<DN>`、状态正常；
- 口令列写入一个**随机不可知**的哈希 ——
  **该账号无法用本地密码登录，也无法通过"重置密码"改成可本地登录**（路由按
  `auth_source=ldap` 恒走域控）。要让它走本地，见 §9；
- 邮箱：目录邮箱与其它账号冲突时**忽略邮箱**（不阻断登录），后续可在用户管理里补；
- 用户名长度上限 **20 字符**（`users.username` 列宽）；超限直接拒绝建号并告警，
  需要调整 `LDAP_USER_FILTER` 或先手工建号；
- 必须能解析出至少一个角色，否则拒绝建号。

## 6. 应急管理员通道（域控故障时的唯一入口）

```bash
LDAP_BYPASS_USERS=ipipadmin,root_ops
```

- 白名单账号**恒走本地口令**，压过一切其它规则（包括 `auth_source=ldap`）；
- 只改变"用哪套口令校验"，不改变任何角色与权限判定；
- **每次使用都写审计**：`action=auth.ldap_bypass`（成功/失败/账号不存在都记）；
- `LDAP_ENABLED=false` 时不写该审计（本就全员本地认证，不存在"绕过"）；
- 审计写失败只告警，不影响登录。

> ✅ **强烈建议**：开启 `LDAP_ENABLED` 之前先配好本项，并**实测一遍**。
> 否则域控一挂，系统就没人能进 —— 这是最常见的自锁事故。
> 这些账号必须保持 `auth_source=local`，且口令由本地维护。

## 7. 排错：「无法登录」决策树

先看**应用日志**（`logs/`）里这一行的 `status` 字段：

```
LDAP 认证失败: username=<u> status=<STATUS> detail=<说明>
```

| status | 含义 | 运维动作 |
|---|---|---|
| `ldap_disabled` | 账号 `auth_source=ldap` 但开关关着 | 要么打开 `LDAP_ENABLED`，要么把该账号改回 `local`（见 §9） |
| `misconfigured` | 配置不全 / **服务账号 Bind 失败** | 检查 `LDAP_SERVER`、`LDAP_BASE_DN`、`LDAP_BIND_DN`、`LDAP_BIND_PASSWORD`。**这是配置问题，不是用户密码错** |
| `unreachable` | 域控网络不可达（连接被拒/超时/半开） | 从应用机 `openssl s_client -connect dc:636` 验证 636/389 连通与证书；查防火墙 |
| `user_not_found` | 过滤器没检索到该用户 | 核对 `LDAP_USER_FILTER` 属性名（AD= `sAMAccountName` / OpenLDAP= `uid`）与 `LDAP_BASE_DN` 范围；确认用户确实在该 OU 下 |
| `ambiguous` | 命中多条 | 过滤器太宽，收紧 `LDAP_USER_FILTER`（例如加 `(objectClass=user)`） |
| `invalid_credentials` | 密码错误 | 让用户重输；确认不是在用旧密码 |
| `disabled` (AD data 533) | 账号在目录中被禁用 | 找域管解禁 |
| `locked` (AD data 775) | 账号在目录中被锁定 | 找域管解锁（多为连续输错触发） |
| `no_role_mapped` | 目录通过但没映射到任何角色 | 检查 `LDAP_GROUP_ROLE_MAP` 键是否与 `memberOf` 对得上；或配 `LDAP_DEFAULT_ROLE` |
| `not_provisioned` | 目录通过但本地无账号且未开自动建号 | 手工建号（`auth_source=ldap`）或开 `LDAP_AUTO_PROVISION` |
| `local_disabled` | 本地账号被禁用 | 在用户管理中启用该账号 |
| `identity_error` / `identity_exception` | 身份落库阶段异常 | 看同一条日志的堆栈；常见为映射表写错、DB 不可用 |

其它高频现象：

| 现象 | 原因与处理 |
|---|---|
| 提示「登录失败次数过多，请5分钟后重试」 | 命中既有防爆破计数（同一用户名 5 次/5 分钟）。等待或换账号；**不要**为此改代码 |
| 域控正常，但所有人都登不上 | 先看 `misconfigured`（服务账号过期是头号原因），再看 `unreachable` |
| 登录成功但权限不对 | 角色问题，与认证无关：查 §4 映射与 `LDAP_SYNC_ROLES_ON_LOGIN` |
| 服务起不来 | 看启动日志里的 `LDAP_ENABLED=true 但 ...` 或 `LDAP_GROUP_ROLE_MAP 无法解析` |

## 8. 审计与核查

启用 LDAP 后，**每一次登录都留痕**（仅当 `LDAP_ENABLED=true`；关闭时零新增写入）。

| action | 何时产生 |
|---|---|
| `auth.login` | 登录成功（`detail.auth_type` = `ldap` 或 `web`） |
| `auth.login.failed` | 登录失败（`detail.reason` = 上表 status 或 `local_credentials_rejected`） |
| `auth.ldap_bypass` | 使用应急本地通道（`detail.bypass=true`） |

`detail` 结构：`{username, auth_type, result, reason, bypass, [note]}`。

查询（需要有审计查看权限的账号）：

```bash
# 全部企业身份相关登录事件
curl -H "Authorization: Bearer <token>" \
  "https://ipip.example.com/api/audit/logs?action=auth.&per_page=50"

# 只看失败（含原因），便于按原因分流
curl -H "Authorization: Bearer <token>" \
  "https://ipip.example.com/api/audit/logs?action=auth.login.failed&per_page=50"
```

直查库（`audit_logs` 表）：

```sql
SELECT created_at, action, user_id, ip_address,
       JSON_UNQUOTE(JSON_EXTRACT(detail, '$.username')) AS username,
       JSON_UNQUOTE(JSON_EXTRACT(detail, '$.reason'))   AS reason
FROM audit_logs
WHERE action LIKE 'auth.%'
ORDER BY created_at DESC LIMIT 100;

-- 应急通道使用记录（应保持低频；异常增多要立即核查）
SELECT created_at, user_id, ip_address, detail FROM audit_logs
WHERE action = 'auth.ldap_bypass' ORDER BY created_at DESC;
```

本地登录日志（既有的 `users_log` 表）同样记录，`login_type` 为 `ldap`。

## 9. 回滚与退役

### 9.1 临时关闭 LDAP（一分钟回滚）

```bash
# /etc/ipip/ipip.env:  LDAP_ENABLED=false
systemctl restart ipip.target
```

关闭后：**本地账号（`auth_source=local`）立即恢复正常登录**，无需改数据。

> ⚠️ **必读**：已由自动建号产生的 `auth_source=ldap` 账号**仍然登不上**（这是刻意的
> fail-close，防止"关掉域控就能用本地口令登录"）。如果需要让某个人在关闭 LDAP 后仍能
> 登录，必须显式改回本地账号并设置口令：
>
> ```sql
> -- 1) 把账号改回本地认证
> UPDATE users SET auth_source='local', external_dn=NULL WHERE username='zhangsan';
> -- 2) 用管理接口/后台重置口令（auth_source 变更不在用户更新白名单内，必须走 SQL）
> ```
> 或者把他加入 `LDAP_BYPASS_USERS`（见 §6）——这是临时抢修的推荐做法。

### 9.2 彻底退役

1. `LDAP_ENABLED=false` 并重启（同上）；
2. 处理 `auth_source='ldap'` 的账号：改回 `local`（并按 §9.1 设口令）或直接停用；
3. 从 `/etc/ipip/ipip.env` 删除全部 `LDAP_*` 配置；
4. （可选）删除 `users.auth_source` / `users.external_dn` 列与索引 —— **不建议**：
   迁移 `0007` 提供回滚 SQL，但删列是生产 DDL，留作死列成本极低；
5. 确认后从 `requirements.txt` 移除 `ldap3`。

## 10. 联调验收清单（上线前必做）

在**测试 LDAP 容器**或客户测试域上逐个跑通；每项都要留下日志/截图记录。

| # | 场景 | 操作 | 期望 |
|---|---|---|---|
| 1 | 正常登录 | 域内用户 + 正确口令 | 登录成功；审计 `auth.login`，`auth_type=ldap` |
| 2 | 密码错误 | 同一用户 + 错误口令 | 提示「用户名或密码错误」；审计 `auth.login.failed`，`reason=invalid_credentials`；**不得**回落本地口令 |
| 3 | 域控不可达 | 停掉 LDAP 容器 / 封 636 端口 | 提示同上；审计 `reason=unreachable`（若服务账号口令错则为 `misconfigured`） |
| 4 | 组变更 | 把用户从 `IPIP-Viewers` 移到 `IPIP-Ops` | 重新登录后权限随之变化（需配 `LDAP_GROUP_ROLE_MAP`） |
| 5 | 账号失效 | 目录内禁用该账号（AD data 533） | 拒绝登录；审计 `reason=disabled` |

补充建议同时验证：

- 6. 应急通道：停掉域控后用 `LDAP_BYPASS_USERS` 账号登录 → 成功 + `auth.ldap_bypass` 审计；
- 7. 重启一次服务确认配置自检与告警是否正常。

> 测试 LDAP 容器（示例，需 docker 环境）：
> ```bash
> docker run -d --name ldap-test -p 389:1389 \
>   -e LDAP_ADMIN_PASSWORD=placeholder-admin-pw \
>   bitnami/openldap:latest
> ```
> 然后在容器内用 `ldapadd` 建 `ou=Users`、`ou=Groups` 与两个用户，组用 `groupOfNames`
> 的 `member` 反查或给用户加 `memberOf`（OpenLDAP 需 `memberof` overlay）。
> **注意**：AD 与 OpenLDAP 的 `memberOf` 行为不同，容器验证通过后仍应在客户真实
> AD 上复核场景 4（组变更）。

### 10.1 实测记录：OpenLDAP 联调（2026-09-11，20/20 通过）

在测试目录 `dc=ipip,dc=local`（slapd 0.0.0.0:389，`memberof` overlay 已加载，
`LDAP_USER_FILTER=(uid={username})`）上逐个打真目录，结果如下：

| 账号 | 目录侧事实 | 期望 | 实测 |
|---|---|---|---|
| `testuser` | memberOf=cn=engineers | `ok` | ✅ `ok`，映射角色 `engineer` |
| `devuser` | memberOf=cn=engineers | `ok` | ✅ `ok`，映射角色 `engineer` |
| `adminuser` | memberOf=cn=admins | `ok` | ✅ `ok`，映射角色 `admin` |
| `disableduser` | 口令无效 | `invalid_credentials` | ✅ 同上 |
| `lockeduser` | 口令无效 | `invalid_credentials` | ✅ 同上 |
| `dupuser` | 同 uid 两条条目 | `ambiguous` | ✅ 同上，日志提示收紧过滤器 |
| `nonexist` | 不存在 | `user_not_found` | ✅ 同上 |
| 正确用户 + 错口令 | — | `invalid_credentials` | ✅ 同上 |
| 空口令 / 空用户名 | — | `invalid_credentials` | ✅ 同上，且**不打域控** |

失败归因路径同批实测通过：服务账号口令错 → `misconfigured`（**不是** `invalid_credentials`）、
域控不可达 → `unreachable`、`LDAP_ENABLED=false` → `ldap_disabled`、缺 `LDAP_BASE_DN`
→ `misconfigured`、过滤器注入 `admin)(|(uid=*` → `user_not_found`（转义生效）。

端到端（真实目录 + 真实登录入口 + 真实落库）也已跑通：自动建号写入
`auth_source=ldap` 与 `external_dn`、本地不留可用口令、角色按组落库、
域控不可达时**即便本地哈希与输入口令一致也拒绝登录**、刷新令牌保留 `auth_type=ldap`。

> **OpenLDAP 与 AD 的预期差异**：`disabled`(AD data 533) / `locked`(775) 这两个状态在
> OpenLDAP 上**无法触发** —— 它的 `invalidCredentials` 不携带 AD 的 data 子码，账号禁用
> 表现为"口令错误"。实测确认 IPIP 对非 AD 目录正确返回 `invalid_credentials`，这是
> **预期行为**，不是缺陷。要验证 `disabled`/`locked` 分支只能在真实 AD 上做。

## 12. 已知坑（踩过，勿再踩）

1. **多条映射不要用逗号/空格并列**：DN 里全是 `=` 和 `,`，这类串会被当成一条映射切开，
   键永远匹配不上 → 全员掉到 `LDAP_DEFAULT_ROLE`。条目分隔符只用 `;` / `|` / 换行；
   组与角色之间优先用 `=>`（`:` 与 `=` 仅在该条目里恰好出现一次时可用）。写错会在
   启动期报错，不再静默降级。
2. **`dc=` 组件不参与匹配**：这是有意的防过度授权设计，不要试图给 `corp` 配映射。
3. **用户名 20 字符上限**：目录里超长登录名会导致自动建号失败（日志有明确提示）。
4. **自动建号账号的本地口令是随机值**：重置本地口令对它无效，别浪费时间排错。
5. **服务账号口令过期**会表现成"所有人都说密码错"——此时日志里是 `misconfigured` 而非
   `invalid_credentials`，别去查网络。
6. **`LDAP_ENABLED=false` 不会让 `auth_source=ldap` 的账号复活**（§9.1）。
7. **开启 LDAP 后每次登录会多一条审计写入**：这是有意的，不要把 `audit_logs` 的增速
   当成异常。
8. **`/api/user/login` 沿用路由级限流，但不写 `login_attempts` 计数**：防爆破计数目前
   只挂在 `/api/auth/login` 上（既有行为，未在本次改动中调整）。若需严格统一，须另开
   任务评审，不要在现场临时改代码。
9. **角色同步依赖外层事务提交**：`sync_user_roles` 只改 ORM 对象，靠登录路由上的
   `@transactional` 落库。**新增任何登录入口都必须带上它**，否则角色同步会静默变成
   空操作（登录成功、权限没变，且没有任何报错）—— 联调时若发现"角色改了但没生效"，
   先查入口有没有 `@transactional`。
10. **映射目标角色不存在 ≠ 数据迁移问题，是部署疏漏**：`LDAP_GROUP_ROLE_MAP` 是环境
   配置、角色是 RBAC 业务数据（每个客户集合不同），迁移只承载产品级种子角色
   （admin/operator/viewer/user）。角色缺失的后果：映射目标**全部**缺失 → 账号被拒登
   （fail-close）；**部分**缺失 → 缺失项静默跳过、可用子集生效（只有 WARNING 日志）。
   防线是部署期自检：`flask ldap-check`（§3 第 5 步），把"配了映射却全员登不上/权限
   缩水"拦在第一个用户登录之前。
