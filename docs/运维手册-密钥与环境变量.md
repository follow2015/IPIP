# 密钥与环境变量运维手册

**相关脚本**：`scripts/install.sh`（步骤 `[4/7] 初始化 .env`）
**最近验证**：2026-09-10 @ 192.168.10.10（Ubuntu 24.04 / 纯测试机）
**关联文档**：`运维手册-备份与恢复.md`

---

## 一、密钥清单

| 变量 | 用途 | 缺失后果 | 轮换影响 |
|------|------|---------|---------|
| `SECRET_KEY` | Flask session 签名 | `FLASK_ENV=production` 时拒绝启动 | 所有用户被登出 |
| `JWT_SECRET_KEY` | JWT 签发/校验 | 同上 | 所有 token 立即失效 |
| `SWITCH_SECRET_KEY` | AES-256-GCM **数据加密密钥** | 拒绝启动（`config.py:692`） | ⚠️ **受密文约束**，见第四节 |

三者均为 **64 字符 hex（32 字节）**。定义位置：`config.py:341`。

---

## 二、自动注入机制（`install.sh` [4/7]）

每次运行 `install.sh` 都会执行一次**幂等**的密钥注入：

| `.env` 现状 | 脚本动作 |
|------------|---------|
| 键已存在、值正常 | **不动** |
| 键已存在、值为空 | 生成随机值覆盖 |
| 键已存在、值为 `change-me*` 占位符 | 生成随机值覆盖 |
| **键整行不存在** | **新增该行并生成随机值** |

注入完成后脚本立即 `set -a; . .env; set +a` 加载到当前进程。

> 设计意图：生产配置对空值/占位符会直接拒绝启动，脚本提前修复，避免部署者漏填。

## 三、缺陷记录（2026-09-10）

### 3.1 「只修不增」导致新密钥永远补不上（已修复）

**现象**：`.env.example` 中已新增 `SWITCH_SECRET_KEY`，但装机后 `.env` 里始终没有该键，直到 `FLASK_ENV=production` 启动 `ipip-monitor` 时才以「启动即崩、被 systemd 反复拉起后 failed」的形式暴露。

**根因**：原实现只遍历 `.env` 的**已有行**，键整行不存在时直接 `continue`，永不新增：

```python
for i, line in enumerate(lines):
    if not m or m.group(1) not in targets:
        continue          # ← 键不存在 → 直接跳过，不会新增
    if val == "" or val.lower().startswith("change-me"):
        lines[i] = ...    # ← 只修改"已存在的行"
```

而 `.env` 来自 `cp .env.example .env`，该步**仅在 `.env` 不存在时执行** → 模板后续新增的键不会回流到已存在的 `.env`。

**修复**：遍历结束后补齐 `targets - present` 的缺失键：

```python
for key in sorted(targets - present):
    lines.append(f"{key}={secrets.token_hex(32)}")
    generated.append(key + "(新增)")
```

**验证结果**：

| 场景 | 结果 |
|------|------|
| 删掉该行后重跑 | `已自动生成随机密钥: SWITCH_SECRET_KEY(新增)` ✅ |
| 紧接再跑一次（幂等） | `SECRET_KEY / JWT_SECRET_KEY / SWITCH_SECRET_KEY 已配置，跳过`，键仍 1 行、值不变 ✅ |
| 全量键差异比对 | `.env` 与模板无其它缺失键（0 个）✅ |

### 3.2 遗留边界：非密钥类新增变量不会自动同步

注入只覆盖上述 **3 个密钥键**。模板里其它新增变量（功能开关、超时配置等）对已存在的 `.env` **不会生效**，需手工同步。比对命令：

```bash
cd /root/ipip-deploy
python3 - <<'PY'
import re
def keys(p):
    return {m.group(1) for m in
            (re.match(r"^([A-Za-z_][A-Za-z0-9_]*)=(.*)$", l) for l in open(p, encoding="utf-8")) if m}
env, ex = keys(".env"), keys(".env.example")
print("模板有而 .env 缺失:", sorted(ex - env) or "无")
PY
```

## 四、⚠️ `SWITCH_SECRET_KEY` 轮换（有密文约束）

### 4.1 它保护什么

| 密文位置 | 内容 | 直接换钥的后果 |
|---------|------|--------------|
| MySQL `switch_credentials` 表 | 交换机登录凭据 | **永久无法解密**，需重新录入设备凭据 |
| **Redis** 快照 `api_key_enc` | AI API Key | AI Key 失效，需在界面重填（若 `AI_API_KEY` 由 env 提供则不受影响） |

- 加密实现：`app/utils/security/encryption.py`（AES-256-GCM，密钥支持 hex/base64）
- 落库迁移先例：`migrations/run_phase3_4.py`

### 4.2 轮换前置检查（必做）

```bash
cd /root/ipip-deploy
for t in switch_credentials ip_switch_info device_switch_ext switch_port_ips; do
  printf "  %-22s " "$t"
  mysql -uipip -p"$MYSQL_PASSWORD" ip_management -N -e "SELECT COUNT(*) FROM $t;"
done
```

- **全部为 0** → 可直接轮换（无密文，无损失）
- **任一非 0** → **禁止直接替换**，必须先迁移密文

### 4.3 正确轮换流程

1. **停机窗口**：`systemctl stop ipip-web ipip-monitor ipip-gateway ipip-celery-ai ipip-celery-voice`
2. **备份**：`.env` + 数据库（见 `运维手册-备份与恢复.md`）
3. **迁移密文**：旧密钥解密 → 新密钥加密。迁移脚本须沿用 `app/utils/security/encryption.py` 的算法与密钥派生方式（**勿照搬** `run_phase3_4.py` 里的 `key.encode()[:32].ljust(32, b'\0')` 截断式派生，与 runtime 实现不一致）
4. **更新 `.env`** 的 `SWITCH_SECRET_KEY`
5. **启服务并验证**：`GET /api/health/check` = 200；抽查一条设备凭据可正常解密

### 4.4 反面案例（2026-09-10 实测踩到）

为验证「缺键补齐」，直接 `sed -i '/^SWITCH_SECRET_KEY=/d' .env` 再跑脚本 → 脚本按预期生成了**新密钥**，但旧密钥从此丢失（`874c8a06…` → `a9c90f0c…`）。

本次因上表 4 张相关表**均为 0 行**，无实际损失。但该操作等同于一次**无迁移的密钥轮换**，若库中已有真实凭据，将直接造成数据不可用。

> **教训**：验证密钥注入逻辑，请使用**新建的临时 `.env`** 做实验，绝不要在真实 `.env` 上删键。

## 五、灾难恢复盲区：备份不含 `.env`

`backup_system.py` 的产物**只含 MySQL dump + `instance/` 数据面，不含 `.env`**。

因此服务器整机损毁后：

- 数据库可以恢复 ✅
- 若 `SWITCH_SECRET_KEY` 同时丢失 → `switch_credentials` 中的密文**永久不可解** ❌

**要求**：`.env` 必须**离线单独留存**（密码管理器 / 密钥保管渠道），并纳入变更管理；含密钥的 `.env` 不得进入代码仓库。

## 六、常见问题

**Q：安装后 `ipip-monitor` 反复重启并进入 `failed`？**
A：检查 `SWITCH_SECRET_KEY` 是否为空。`FLASK_ENV=production` 时 `config.py:692` 强制校验，缺失即拒绝启动。修复：重跑 `install.sh`（[4/7] 会自动补齐）或手工补该键后重启服务。

**Q：`.env.example` 里加了新变量，部署后没生效？**
A：见 3.2，非密钥键不会自动同步，需手工追加。

**Q：安装期依赖类报错（pnpm / Node 版本 / starlette 冲突）？**
A：见 `IPIP功能缺口评审报告-部署仓库视角.md` 的缺陷清单。
